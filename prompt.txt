## 2. 핵심 구현 방향

이 프로젝트는 교사가 직접 출제한 문제를 학생이 풀고, 획득한 코인을 활용해 던전을 진행하는 학습 게임이야.

전체 학습 흐름은 다음과 같아.

교사 문제 출제 → 문제 은행 저장 → 활동 생성 및 문제 선택 → 학생 퀴즈 풀이 → 코인 획득 → 능력 구매 → 던전 플레이 → 결과 저장 및 교사 분석

따라서 이번 문제 은행 구현부터 이후 활동 생성과 학생 게임에 연결할 수 있도록 데이터 구조를 설계해 줘.

- 교사가 문제와 보기, 정답을 직접 등록할 수 있어야 함.
- 과목·난이도·학습 개념을 분류하고 검색 및 필터링할 수 있어야 함.
- 등록한 문제를 수정하고 삭제할 수 있어야 함.
- 활동 생성 시 문제 은행에서 문제를 선택해 연결할 수 있어야 함.
- 활동에 사용된 문제는 원본 문제 수정이나 삭제의 영향을 받지 않도록 필요한 데이터 복사 구조를 검토할 것.
- 학생에게 정답 데이터가 노출되지 않도록 문제 데이터와 채점 구조를 분리할 것.
- 기존에 구현된 Firebase 및 교사 플랫폼 구조를 유지할 것.

## 1. 5-0 채점 방식
서버 채점(Cloud Functions)을 채택할게.

- 학생에게 정답 데이터가 노출되지 않도록 설계
- 학생의 답안을 서버로 전달하고 서버에서 채점
- 채점 결과와 코인 지급이 조작되지 않도록 처리
- 중복 요청이나 반복 제출로 보상이 중복 지급되지 않도록 처리
- Firestore 보안 규칙과 연계해 검토

기존 AGENTS.md의 npm·빌드 도구 사용 제한은 서버 함수에 한해 필요한 범위에서 수정해 줘.

단, 기존 학생 게임과 교사 플랫폼의 Firebase CDN 기반 구조는 유지하고, 서버 함수 구현에 필요한 Node.js와 Firebase CLI만 별도로 허용해 줘.

Blaze 요금제의 비용 및 배포 전 필요한 설정도 정리해 줘.

## 2. 5-1 동시 활동 수
학급당 동시에 진행할 수 있는 활동은 1개로 제한할게.

- 한 학급에서 진행 중인 활동은 하나만 허용
- 진행 중인 활동이 있으면 새 활동 시작 제한
- 활동 종료 후 새로운 활동 생성 가능
- 학생은 해당 학급의 진행 중인 활동에 참여

- 교사와 학생의 전체 이용 흐름 테스트
- Firebase 서버 채점 및 보상 지급 검증
- 중복 제출과 중복 보상 방지 검증
- 네트워크 오류 및 재시도 처리
- Firestore 보안 규칙 점검
- 기존 학급 관리 기능(3-5, 3-1, 3-6, 3-7) 회귀 테스트
- 자동화 가능한 테스트 실행
- 문서와 tasks.md 진행 상태 갱신
- 단계별 커밋

## 구현 원칙
1. 기존에 구현한 문제 은행, 학급 관리, Firebase 인증 및 서버 채점 기능을 유지할 것.
2. 교사가 직접 만든 문제와 활동이 학생 게임에 실제로 연결되어야 함.
3. 교사 플랫폼과 학생 게임의 데이터 흐름이 끊기지 않도록 구현할 것.
4. 임시 데이터나 화면만 만드는 것으로 완료 처리하지 말고 실제 저장과 조회까지 연결할 것.
5. 보안상 정답과 보상 처리는 서버에서 검증할 것.
6. 이미 확정한 사항을 다시 질문하지 말고 합리적인 기본값으로 진행할 것.
7. 기존 코드 구조를 먼저 파악하고 필요한 범위에서만 수정할 것.
8. 실제 실행하지 않은 테스트는 완료했다고 표시하지 말 것.
9. 구현이 막히는 중대한 문제가 아니라면 중간에 멈추지 말고 계속 진행할 것.

## 최종 목표
교사가 문제를 출제하고 수업 활동을 생성하면 학생들이 참여 코드로 입장해 퀴즈를 풀고 코인을 획득한 뒤 던전을 플레이할 수 있어야 해. 플레이 결과는 저장되고 교사는 학급 및 학생별 학습 결과를 확인할 수 있어야 해.

이번 작업에서는 기능 간 연결을 최우선으로 해 줘. 모든 기능을 한꺼번에 완벽하게 꾸미기보다 실제로 처음부터 끝까지 작동하는 서비스를 완성하는 데 집중해 줘.

작업을 마친 뒤에는 다음을 정리해 줘.
- 구현 완료 기능
- 아직 구현되지 않은 기능
- 실행한 테스트와 결과
- 내가 직접 해야 할 Firebase 설정 및 배포 작업
- Live Server에서 확인해야 할 항목
- 다음 작업에서 가장 먼저 처리할 사항

기존 구현 범위에 교사 간 협력 기능과 학습 분석 기능을 추가해 줘.

## 1. 학생별 맞춤 피드백
- 학생별 정답률, 오답 문제, 취약 학습 개념 분석
- 학습 결과에 따른 개별 피드백 제공
- 취약 개념과 연관된 문제 추천
- 활동별 학습 변화 확인

## 2. 학급별 학습 분석
- 학급 전체 및 학생별 정답률
- 문제별·학습 개념별 정답률
- 학생별 학습 수준과 취약 영역
- 활동 참여율 및 완료율
- 교사가 다음 수업의 보충 학습 내용을 판단할 수 있는 요약 제공

분석 결과는 실제 저장된 학생 응답과 활동 결과를 기반으로 산출해 줘. 데이터가 부족하면 분석 결과를 임의로 생성하지 말고 분석 불가 또는 데이터 부족으로 표시해 줘.

## 3. 교사 간 공유 문제은행
- 개인 문제은행과 공유 문제은행 분리
- 교사가 자신의 문제를 공유 문제은행에 등록
- 다른 교사가 과목, 난이도, 학습 개념 등으로 문제 검색
- 문제 미리보기 및 개인 문제은행으로 가져오기
- 가져온 문제는 원본과 독립적으로 수정할 수 있도록 복사
- 원본 제작자 및 출처 정보 표시
- 공유 문제의 수정·삭제 권한 관리

## 구현 원칙
- 기존 개인 문제은행과 활동 생성 기능을 유지할 것.
- 공유 문제를 가져온 뒤 기존 활동 생성 과정에서 바로 사용할 수 있도록 연결할 것.
- 교사별 데이터 접근 권한과 Firestore 보안 규칙을 고려할 것.
- 학생의 학습 결과는 해당 학급 담당 교사에게만 공개할 것.
- 개인 식별 정보가 공유 문제은행에 노출되지 않도록 할 것.
- 맞춤 피드백은 실제 학습 데이터에 근거한 규칙 기반 분석부터 구현하고, 근거 없는 AI 분석 결과를 생성하지 말 것.
- 기존 6~10단계 구현과 연계해 진행하고 별도의 승인 없이 합리적인 구조로 구현할 것.
- 구현 범위가 커지면 핵심 기능부터 완성하고 미구현 항목은 tasks.md에 명확히 남길 것.

이전 작업을 이어서 진행하자.

현재 가장 중요한 것은 실제 Firebase 환경에서의 검증이다. 지금까지 가짜 Firebase 환경에서만 테스트했으므로 실제 배포 및 권한 검증을 우선한다.

1. 먼저 현재 Git 상태와 tasks.md, work-log.md를 확인하고 이전 작업의 진행 상황을 파악해 줘.
2. 변경된 Firestore 규칙과 Cloud Functions를 실제 Firebase에 배포할 준비를 해 줘. 배포 전 프로젝트 설정, 리전, 환경변수, 보안 규칙을 점검해 줘.
3. 실제 배포가 필요한 명령어와 내가 직접 수행해야 하는 단계를 구분해 안내해 줘. 배포 권한이나 결제 설정 등 내가 직접 처리해야 하는 부분에서만 멈춰 줘.
4. 배포 후 다음 항목을 실제 Firebase 환경에서 검증할 수 있도록 테스트 절차를 정리해 줘.
   - Cloud Functions 6개 정상 등록 및 실행
   - 공유 문제은행의 교사 A/B 권한 분리
   - 공유 문제 가져오기 후 원본과 복사본의 독립성
   - 원본 공유 문제의 소유자가 아닌 교사의 삭제 차단
   - 학생 계정의 공유 문제은행 접근 차단
   - 공유 문서에 이메일과 실명 미저장
   - 실제 학생 응답 결과에 기반한 맞춤 피드백과 복습 문제 추천
   - 응답 데이터가 부족할 때 '데이터 부족' 표시

5. 특히 결과 분석 기준 임계값과 12-7, 12-8 화면 구성은 임의로 확정하지 말고 현재 구현 상태와 설계 문서를 확인해 정리해 줘. 내가 확인해야 할 결정 사항만 모아서 제시해 줘.

테스트 결과는 실제 Firebase에서 확인한 항목과 코드 수준에서만 확인한 항목을 구분해 기록해 줘. 확인하지 않은 기능을 정상 작동한다고 표시하지 마.

시간이 부족하므로 작은 단계마다 승인을 요청하지 말고 가능한 점검과 준비 작업은 이어서 진행해 줘. 실제 배포나 데이터 변경처럼 내가 직접 승인해야 하는 작업에서만 멈춰 줘.

현재 진행 중인 Firebase 배포 및 실제 환경 검토 작업을 먼저 마무리하자.

다만 이번 작업은 기존 개발 범위를 대체하는 것이 아니라, 기존 작업을 마무리하기 위한 검증 단계라는 점을 기억해 줘.

1. 현재 진행 중인 Firebase 배포와 Cloud Functions, Firestore 규칙 검토를 마무리해 줘.
2. 실제 Firebase 환경에서 확인한 항목과 아직 확인하지 못한 항목을 구분해 기록해 줘.
3. 공유 문제은행의 교사 A/B 권한, 학생 계정 접근 제한, 문제 복사 및 원본 독립성, 개인정보 미저장 여부를 검증해 줘.
4. 결과 탭의 학습 분석과 맞춤 피드백도 실제 데이터로 확인해 줘. 응답 데이터가 부족한 경우에는 '데이터 부족'으로 표시되는지 확인해 줘.
5. 12-7, 12-8의 분석 기준 임계값과 화면 구성은 현재 구현 상태를 확인한 뒤 결정이 필요한 사항만 정리해 줘.

위 검토가 끝나면 다시 원래 개발 범위로 돌아와 줘.

- 기존 tasks.md에 기록된 미완료 작업을 확인하고 이어서 진행할 것
- 특히 기존 6~10단계의 학생 게임 핵심 흐름, 퀴즈와 던전 연동, 결과 저장, 교사 대시보드, 게임 완성도를 마무리할 것
- 새롭게 추가한 공유 문제은행, 학급별 학습 분석, 학생별 맞춤 피드백은 기존 기능과 통합하되, 이미 검토한 내용을 불필요하게 다시 구현하지 않을 것
- 기존 설계 문서와 작업 기록을 기준으로 진행 상황을 갱신할 것

Firebase 검토가 끝났다는 이유로 프로젝트 전체 작업이 완료된 것으로 판단하지 말아 줘. 원래 계획했던 학생 게임과 교사 플랫폼의 전체 기능이 완성될 때까지 개발을 이어가는 것이 목표야.

작업을 작은 단위로 나누어 매번 승인받기보다는 가능한 범위에서 이어서 진행해 줘. 설계상 중요한 결정이나 실제 사용자 확인이 필요한 사항에서만 질문해 줘.

[작업 방식]
- 토큰과 대기 시간을 최소화해 줘.
- 이미 확인한 파일이나 설계 내용을 불필요하게 다시 분석하지 말 것.
- 긴 계획이나 진행 상황 설명 대신 실제 코드 수정과 기능 구현을 우선할 것.
- 여러 작업을 묶어 한 번에 진척시킬 것.
- 작업 단위마다 변경 파일, 구현 내용, 테스트 결과만 짧게 보고할 것.
- 중간에 불필요한 승인이나 확인을 요청하지 말 것.
- 작업이 끝날 때까지 가능한 다음 미완료 항목으로 바로 넘어갈 것.
- 막히거나 중요한 설계 결정이 필요한 경우에만 질문할 것.
- 테스트하지 않은 기능을 완료했다고 표시하지 말 것.

목표는 설명을 길게 하는 것이 아니라 실제 작동하는 결과물을 빠르게 완성하는 것이야.
