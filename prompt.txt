로그아웃 테스트는 정상적으로 완료했어. 다음 내용에 따라 tasks.md를 수정해 줘.

아래 순서로 작업을 재배치해 줘.
1. 3-3 참여 코드 규칙 결정
2. 3-4 학급 생성 및 참여 코드 발급

4. 3-1 메뉴 및 화면 전환
5. 3-6 학급 상세 화면

## 2. 참여 코드 규칙
- 숫자 6자리로 확정 (예: 482913)
- 무작위 생성
- 기존 활성 참여 코드와 중복 방지
- 다른 교사의 학급에 무단 접근하지 못하도록 Firestore 보안 규칙 유지

## 3. 반드시 포함할 학급 관리 기능
- 3-4: 학급 만들기 버튼, 학급명 입력, 참여 코드 자동 발급 및 Firestore 저장
- 3-5: 내가 만든 학급 목록 조회 및 표시
- 3-6: 학급 선택 후 상세 화면으로 이동

각 작업에 구체적인 Live Server 확인 조건을 작성해 줘.

## 1. 이후 작업 순서

다음 순서로 개발 단계를 구성해 줘.

1. **문제 은행**: 문제 등록·수정·삭제, 과목·난이도·학습 개념 분류, 기존 12문제 정리
2. **수업 활동 관리**: 문제 세트 선택, 활동 시간 설정, 생성·대기·시작·종료
3. **학생 참여 시스템**: 6자리 코드와 닉네임으로 참여, 교사 활동 대기 및 시작 신호 수신
4. **게임 연동**: 퀴즈 → 코인 획득 → 능력 구매 → 던전 플레이 → 결과 저장
5. **결과 분석**: 학생별 정답률·오답·던전 기록, 학급 통계 및 취약 개념 분석
6. **차별화 기능**: 오답 도감, 재도전 및 학급 공동 보스 등

각 단계는 실제 데이터와 화면이 연결되는 작업 단위로 세분화해 줘.

## 2. 기존 미정 사항 반영

다음 항목은 해당 단계에서 결정하도록 유지해 줘.

- 6-0 채점 방식: 서버 채점 및 정답 비노출 방안
- 5-1a 학습 개념: 입력 방식, 필수 여부, 기존 12문제의 개념 분류
- 8a-1 취약 개념 기준: 오답률 및 최소 풀이 횟수
- 4-5 예외: Firebase 없이 단독 플레이 허용 여부
- 삭제된 학급의 참여 코드 재사용 여부
